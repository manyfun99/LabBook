### 3.2 바로 다음: 2차 계획 작성

`/forge:plan-gen` 으로 **"주식 오픈소스 조사 실행 2차 — 골드 보정(`judge --gold`) → rubric-v1 확정 → 전수 정밀 판정"** 을 쓴다. 인계 원래 순번으로는 8~9단계다. 브랜치는 PR #3 이 머지된 뒤 main 에서 새로 판다. 머지 전이면 `feature/stock-oss-run-1` 에서 딴다.

계획 작성 전에 확인해 둔 코드 거동은 다음과 같다(`labbook/judge.py`, `labbook/llm.py`).
- `judge --gold`
  - `gold.jsonl` 의 레포마다 opus 를 1번씩, 모두 20번 부른다. **DB 에는 쓰지 않는다.**
  - 결과는 `reports/gold-v1.md` 에 쓰고, 실행할 때마다 덮어쓴다.
  - 판정에 실패한 레포는 일치율 계산에서 빼고 리포트에 적는다.
- 확정 기준: 축별 ±1 일치율이 70% 이상이다(각 축마다).
- 전수 `judge` 대기열: `scoped=include` 이고 `triaged` 가 include·unsure 이며, `judgment(full)` 이 없는 레포다. **현재 430개**(원 계획 추정은 약 500).
  - 레포당 opus 1회. 입력은 README 앞 30,000자와 댓글순 이슈 30개다.
  - 레포 단위로 커밋하고, `--limit N` 으로 나눠 돌린다. 골드 레포도 여기서 정식 판정된다.
- 인용 검사: 실패하면 같은 호출 안에서 1회 재시도한다. 또 실패하면 `screening(judged, error)` 로 남고 다음 실행 대기열에 다시 들어간다. 1차와 같은 이유로 **error 재시도 상한 규칙이 필요하다.**

2차 계획에서 정해야 할 것:
- **골드 채점자 변경을 성공 기준에 어떻게 반영할지.** 70% 기준을 그대로 둘지, 보정이 실패했을 때의 대응을 어떻게 할지(원 계획 §5.2 기각 대안 2 인 다중 계열 API 판정 재검토)를 정한다.
- **루브릭 조정 반복 상한.** 20개에 맞추다 보면 과적합된다. 조정할 때마다 `gold-v1.md` 를 보존할지(덮어쓰기라서)도 정한다.
- **전수 판정 분할과 소요 추정.** `--gold` 20회 실행 시간으로 레포당 시간을 재서 430개의 소요를 추정한다. 구독 한도를 보며 하루에 몇 개씩 돌릴지 정한다.
- 1차처럼 코드 변경 없는 운영 실행이 될 가능성이 높다. 그러면 6장에 확인 열을 두는 형식을 재사용한다.

## 4. 운영 주의

- 명령은 레포 루트에서 `python3 -m labbook …` 으로 실행한다. 작업 DB 기본 경로는 `labbook.db` 이고 `--db` 로 바꿀 수 있다(전역 옵션이라 서브명령 앞에 둔다).
- `claude -p` 판정은 로컬 로그인 세션(구독)을 쓴다. 도구 없이, 세션을 저장하지 않고, cwd `.cache/llm/` 로 격리해 돌린다.
- 실패한 레포는 `screening` 에 `error` 로 남고 다음 실행에서 자동으로 재시도된다. 계속 실패하는 레포가 있으면 대기열이 0 이 되지 않으니 재시도 횟수에 상한을 둔다.
- `refresh` 의 "같은 날"은 실행을 시작한 시점의 UTC 날짜다(KST 09:00 에 바뀐다). 같은 UTC 날짜에 다시 돌리면 스냅샷이 없는 레포만 조회한다. 첫 실행에서 조회 오류가 난 레포는 `scoped` 행이 없으므로, 같은 날 재실행해야 1단 대기열에 들어간다.
- DB 에 쓰는 명령(collect·refresh·triage·judge)은 동시에 돌리지 않는다.
- README 캐시(`.cache/readme/`)는 7일 뒤 만료된다. awesome 목록은 매번 새로 읽는다.
- 퍼널의 "의심 표시"는 제외 사유가 아니라 사람이 확인할 대상이다(예: prism-insight 은 watchers 비율 때문에 `low_watchers` 가 선다).
- 재현율 점검·기준 목록 작성 스크립트는 세션 스크래치에서만 돌렸고 레포에 없다. 코드는 1차 계획 §3.1·§3.2 에 있다. 두 번째로 쓰게 되면 `labbook recall` 명령으로 승격한다(1차 §7.3).

PR #1 코드 리뷰의 남은 권고는 `20260927-코드리뷰-잔여-권고-정리.md` 로 모두 반영했다(PR #2). 범위 밖 작업(롱테일, 재판정, 자동 주간 실행, 의미 검색 등)은 원 계획 §7.3 에 있다.
