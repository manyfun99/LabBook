## 2. 정한 것 (근거는 계획 문서의 해당 절)

| 결정 | 내용 |
|---|---|
| 구조 (§5.1) | 수집·지표·퍼널은 결정론적 Python이 맡는다. 1단 선별은 `claude -p` sonnet(20개 묶음), 2단 정밀 판정은 opus(1개씩)로 한다. 심층분석·브레인스토밍·조회는 대화형 스킬로 한다 |
| 기록 (§3.1-D) | `labbook.db` 는 작업 DB 로 gitignore 한다. git 에는 `data/*.jsonl`(`export`)만 커밋하고, 새 환경에서는 `import` 로 재구성한다 |
| 범위 (§3.1 B-2) | 유명 ≥1000★ ∪ 라이징(Δ30≥300 또는 Δ30/★≥20%·★≥100) ∪ 한국 쿼리 출처 ≥50★ ∪ 사용자 스타. 롱테일은 1차 결과를 본 뒤 결정한다 |

| 검증 가설 (§2.3) | 원페이저 3개 중 1개 이상이 "검증 진행" → **판정일 2026-10-24**. 툴킷을 4주간 주 1회 이상 사용(`log.md` 에 `## [날짜] use \| owner/repo`) → **판정일 2026-11-21** |

**조사에서 확인한 사실** (2026-09-26 실측)
- GitHub stargazers 목록 API 는 2026-06-30 부터 admin 전용이라 404 가 난다.
- 대신 `repositories/{id}/stargazers/history` 가 동작한다. 최신 주가 먼저 오고, 주는 일요일에 시작하며, 한 페이지가 30주다.
- OSS Insight 트렌드와 ClickHouse github_events 는 데이터 공백이 커서 쓰지 않는다.
- 가짜 스타 레포의 상당수가 악성코드 위장이다. 심층분석 스킬은 얕은 clone 만 하고 실행을 금지한다.

**계획 대비 바뀐 구현** (PR #1 본문 "계획 대비 변경")
- `refresh` 는 후보마다 repo·history API 를 둘 다 불러서, 후보 약 4,500개 기준 **주당 약 2시간** 걸린다.
- 의심 플래그의 "커밋 수 과소"는 fork/★ < 1% 로 대신한다.
- `judgment.model` 에는 실제 모델 ID 가 기록된다.

   - 오래 걸리므로 백그라운드로 돌린다.
   - 중단돼도 같은 날 다시 돌리면 이미 스냅샷이 있는 레포는 건너뛴다.
4. **재현율 점검**: 기준 목록이 `entity` 에 있는지 대조한다. 누락이 5%를 넘으면 `config.json` 쿼리를 보강하고 2~3을 반복한다.

6. **1단 선별**: `python3 -m labbook triage stock-oss --limit 200` 을 나눠 돌린다(약 800개, sonnet 호출 약 40회).
7. **골드셋 (사용자 작업)**

   - 대표 8개는 1단 결과의 카테고리를 보고 함께 고른다.
8. **보정**: `python3 -m labbook judge stock-oss --gold` → `reports/gold-v1.md` 를 보고 `rubric-v1.md` 를 조정한다. 축별 ±1 일치율 70% 이상이면 v1 로 확정한다(DB 에는 쓰지 않는다).
9. **정밀 판정**: `python3 -m labbook judge stock-oss --limit 50` 을 며칠에 나눠 돌린다(약 500개, opus). 구독 한도를 본다.
10. `python3 -m labbook funnel stock-oss` → `select stock-oss` → 사용자 확인·`--add` → `select … --confirm`.
11. `labbook-deep-dive` 스킬로 15개 + 사용자 지정분을 심층분석한다.
12. `labbook-brainstorm` 스킬로 원페이저 3개(사용자가 고름)와 `toolkit.md` 를 만든다. 검증 트랙은 해당 제품 레포(GuruNote 또는 신규)에서 `/forge:plan-gen` 으로 연다.

각 단계 뒤에 `export` → `data/*.jsonl` 커밋을 한다. 명령마다 `topics/stock-oss/log.md` 에 한 줄이 자동으로 남는다.

## 4. 운영 주의

- 명령은 레포 루트에서 `python3 -m labbook …` 으로 실행한다. 작업 DB 경로는 기본 `labbook.db` 이고, `--db` 로 바꿀 수 있다.
- `claude -p` 판정은 로컬 로그인 세션(구독)을 쓴다. 도구 없음, 세션 미저장, cwd `.cache/llm/` 로 격리돼 있다.
- 실패한 레포는 `screening` 에 `error` 로 남고 다음 실행에서 자동으로 다시 시도한다. 레포 하나의 오류가 전체를 멈추지 않는다.
- README 캐시(`.cache/readme/`)는 7일 뒤 만료된다. awesome 목록은 매번 새로 읽는다.
- 퍼널의 "의심 표시"는 제외 사유가 아니다. 사람이 확인할 대상이다(예: prism-insight 은 watchers 비율 때문에 `low_watchers` 가 선다).
