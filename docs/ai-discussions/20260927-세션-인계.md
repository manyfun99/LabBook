## 4. 운영 주의

- 명령은 레포 루트에서 `python3 -m labbook …` 으로 실행한다. 작업 DB 기본 경로는 `labbook.db` 이고 `--db` 로 바꿀 수 있다(전역 옵션이라 서브명령 앞에 둔다).
- `claude -p` 판정은 로컬 로그인 세션(구독)을 쓴다. 도구 없이, 세션을 저장하지 않고, cwd `.cache/llm/` 로 격리해 돌린다.
- 실패한 레포는 `screening` 에 `error` 로 남고 다음 실행에서 자동으로 재시도된다. 계속 실패하는 레포가 있으면 대기열이 0 이 되지 않으니 재시도 횟수에 상한을 둔다.
- `judge --gold` 는 실패 사유를 남기지 않는다. 구독 한도 여부는 격리된 확인 호출(`.cache/llm` 에서 `claude -p --tools ""`)로 가린다. 레포 루트에서 격리 없이 부르면 레포 컨텍스트가 로드된다.
- `refresh` 의 "같은 날"은 실행을 시작한 시점의 UTC 날짜다(KST 09:00 에 바뀐다). 같은 UTC 날짜에 다시 돌리면 스냅샷이 없는 레포만 조회한다. 첫 실행에서 조회 오류가 난 레포는 `scoped` 행이 없으므로, 같은 날 재실행해야 1단 대기열에 들어간다.
- DB 에 쓰는 명령(collect·refresh·triage·judge)은 동시에 돌리지 않는다.
- README 캐시(`.cache/readme/`)는 7일 뒤 만료된다. awesome 목록은 매번 새로 읽는다.
- 퍼널의 "의심 표시"는 제외 사유가 아니라 사람이 확인할 대상이다(예: prism-insight 은 watchers 비율 때문에 `low_watchers` 가 선다).
- 재현율 점검·기준 목록 작성 스크립트는 세션 스크래치에서만 돌렸고 레포에 없다. 코드는 1차 계획 §3.1·§3.2 에 있다. 두 번째로 쓰게 되면 `labbook recall` 명령으로 승격한다(1차 §7.3).
