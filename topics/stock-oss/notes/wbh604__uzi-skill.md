## 무엇·어떻게

UZI-Skill(游资 Skills)은 종목 하나를 넣으면 HTML 리포트를 만들어 주는 에이전트용 플러그인이다. Claude Code(`stock-deep-analyzer` 플러그인)·Codex·Cursor·Gemini CLI·Hermes·OpenClaw 에서 쓰고, `python run.py <ticker>` 로 CLI 에서 바로 돌릴 수도 있다. clone HEAD `650788c54a9b2e042bf7f983f16dbf8d727fce1d`, 버전 v3.9.4, MIT 라이선스. 2026-04-16 에 만들어졌고 ★7,038·포크 984 다.

- 구조: `skills/deep-analysis/scripts/` 에 Python 코드가 전부 있다. `fetch_*.py` 22개(22개 차원 수집기)가 데이터를 모으고, `lib/pipeline/`(v3.0 기본 경로)이 수집→점수→합성을 맡는다. `lib/investor_criteria.py`·`investor_evaluator.py` 는 66명 페르소나에 규칙 242개를 적용하는 규칙 엔진이고, `personas/*.yaml` 은 에이전트 롤플레이용 페르소나 정의, `lib/self_review.py` 는 리포트를 내기 전 13개 항목을 기계적으로 점검하는 게이트다(critical 이 하나라도 있으면 `RuntimeError` 로 HTML 생성을 막는다). `lib/report/` 는 HTML 렌더링이다. 이 밖에 `screen.py`(A주·홍콩 전 시장 일일 관찰 목록), `--versus`(2~4종목 비교), `--portfolio`(CSV 포트폴리오) 기능이 있다. 테스트는 pytest 67개 파일이다.
- 분석 흐름: Stage 1(스크립트가 데이터 수집·DCF 등 모델 계산·규칙 엔진으로 뼈대 점수 산출) → 에이전트 개입(deep 단계에서는 필수: `panel.json`+YAML 을 읽고 66명 역할을 맡아 `agent_analysis.json` 작성) → Stage 2(합성·자가 점검·리포트). lite/medium 은 롤플레이 없이 규칙 엔진 점수만으로 HTML 이 나온다. 최종 점수는 `overall = fund_score × 0.6 + consensus × 0.4` 이다.
- "22개 기관 분석법": anthropics/financial-services-plugins 의 방법론을 옮겨 A주 파라미터(rf 2.5%·ERP 6%·세율 25%·영구성장률 2.5%)에 맞춘 것이다. DCF·Comps·3표 예측·Quick LBO·M&A 증감 같은 밸류에이션 모델도 있지만, 조간 브리핑·DD 체크리스트·촉매 일정·포터 5력 같은 워크플로·템플릿까지 합친 숫자다. "JPM/GS 형식"은 리포트 서식을 뜻할 뿐 기관 검증을 뜻하지 않는다.
- 데이터 소스: 모두 무료이고 키가 없다. 동방재부 push2·akshare·巨潮 cninfo·雪球·텐센트·시나·baostock·yfinance·DuckDuckGo(`ddgs`)·웨이보/즈후/바이두/더우인/터우탸오/빌리빌리 핫검색 JSON 을 쓴다. 공급원이 여럿으로 이어진 fallback 구조다. 선택 사항으로 동방재부 妙想 API(`MX_APIKEY`, 무료 발급)와 雪球 로그인(Playwright 쿠키)이 있다. Playwright 로 브라우저 스크래핑 보강도 한다.
- 한국 시장: `lib/market_router.py` 에 `.KS`/`.KQ` → KRX/KOSDAQ·KRW 라우팅이 있고 README 에 `005930.KS` 예시가 있다. 실제 데이터는 Yahoo/yfinance 공용 경로만 탄다. DART·KRX 수급 같은 한국 전용 소스는 없다.
- LLM: 레포 코드는 LLM API 를 직접 부르지 않는다. 판단은 호스트 에이전트(Claude·Codex 등)의 몫이고 모델도 사용자가 고른다(#78 메인테이너 답: "越强的模型越好，不依赖多模态"). `build_system_message` 를 prefix 가 바뀌지 않게 설계해 prompt cache 를 노린다.
- 1회 실행 비용: 데이터는 0원. 소요 시간은 README 기준 lite 1~2분, medium 5~8분, deep 15~20분이다. 비용은 에이전트 토큰에서 나오는데 deep 단계에서 66명 롤플레이를 하면 커진다. #16 에서 Codex 토큰 소비·시간 과다가 이미 알려진 문제로 올라왔고, 열린 이슈 #110·#111 은 lite 에서도 22개 수집기를 전부 돌려 API 695회·22분이 걸린다는 버그다.

## 인디 관점 메모

- 공백: (1) 성과 추적 — 사용자가 "이걸로 돈 벌었나"를 묻지만 관찰 목록 장부에는 수익 추적·표본 외 검증이 없다고 저자가 인정했다. 페르소나 판정·관찰 후보를 시점 고정 스냅숏으로 쌓고 포워드 수익을 공개하는 추적 레이어가 비어 있다. (2) 호스팅 UI — docker·독립 UI 요청을 거절했다. 설치 문제(Hermes·Gemini·네임스페이스)가 반복되므로 "종목코드 입력 → 리포트" 웹 서비스 수요가 있다. 단 무료 소스의 반크롤링·약관 문제와 중국 규제(종목 추천 금지 태도, 해외 단톡방 회피)를 생각하면 중국 대상 상용화는 위험하다. (3) 한국판 — 같은 구조(무료 데이터 + 투자 대가 페르소나 패널 + 기관식 템플릿 + 공유 카드)에 DART·KRX·네이버 금융 데이터와 한국 투자자 페르소나를 넣은 제품이 없다.
- 차용: 규칙 엔진 뼈대 점수를 먼저 내고 에이전트 롤플레이가 이유를 달아 덮어쓰게 하는 2단 구조와 `analysis_input_hash` 로 오래된 롤플레이를 재사용하지 못하게 막는 장치, critical 이 있으면 리포트 생성을 물리적으로 막는 `self_review` 게이트, 데이터가 비면 기본값을 채우지 않고 `_data_gaps.json` 으로 드러내는 설계, prefix 를 고정한 system message(prompt cache), 1080×1920 SNS 공유 카드로 바이럴을 만드는 출력.
