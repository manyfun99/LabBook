## 무엇·어떻게

금감원 Open DART API 를 감싼 MIT 파이썬 라이브러리 겸 CLI 다(★477, 30일 +4, 포크 117, clone HEAD `9969a8c`, 2026-08-11). FinanceData.KR 1인이 2020-02 부터 관리한다. 코드는 `opendartreader/` 아래 약 1,300줄로 작다.

- 구조: `OpenDartReader` 클래스(`dart.py`)가 기능별 모듈을 묶는다. `dart_list`(공시검색·기업개황·원문·고유번호), `dart_report`(사업보고서 주요정보 28항목), `dart_finstate`(주요계정·전체 재무제표·XBRL 원본·표준계정체계), `dart_share`(대량보유·임원 소유보고), `dart_event`(주요사항보고 36종), `dart_regstate`(증권신고서 6종), `dart_utils`(DART 웹 스크래핑: 당일 공시목록+시각 `list_date_ex`, 하위문서 `sub_docs`, 첨부파일, 제출자 검색 `list_presenter`)다. 0.3 대에서 `click` 기반 CLI `dart`(JSON 기본 출력, `--pretty`)와 `.env` 의 `DART_API_KEY` 자동 로드가 추가됐다. README 는 CLI 절을 "CLI 사용자와 AI를 위한" 이라고 이름 붙여 에이전트가 셸로 부르는 용도를 겨냥한다. MCP 서버는 없다.
- 핵심 가치: 종목코드·회사명 → DART 고유번호 변환(`corpCode.xml` 을 하루 한 번 받아 `./docs_cache/` 에 pickle 로 캐시), JSON/XML → pandas DataFrame, 페이지 자동 순회.
- 데이터 소스: `opendart.fss.or.kr/api/*`(API 키 필요, 무료)와 `dart.fss.or.kr` 웹 페이지 스크래핑(키 불필요). 스크래핑 쪽은 DART 홈페이지 개편 때마다 깨진다(#32·#39·#57).
- LLM: 쓰지 않는다.
- 1회 실행 비용: 0원. 제약은 Open DART 의 키당 일일 호출 한도와 스크래핑 속도(요청 사이 0.1초 대기)다.

## 성과 주장의 신뢰도

1. 주장 목록: 수익률·적중률·샤프·초과수익 주장이 없다. README·README.en·docs 노트북에서 `수익률|backtest|outperform|sharpe` 를 찾아도 투자 성과 주장은 나오지 않는다. 성과 외 주장도 README 의 건수 예시("3,139 건" 등, 특정 기간 공시 수) 정도로, 기능 설명이다.
2. 면책 문구: 없다. 공시 원천 데이터를 그대로 돌려주는 도구라 필요성도 낮다.
3. 검증 수단: 백테스트가 없으므로 기간·수수료·look-ahead·컷오프 이후 구간 항목은 해당 없음. 데이터 정확성 검증 장치도 약하다. `opendartreader/tests/test_basic.py` 는 `assert 1 == 1` 과 실제 API 호출 예제뿐이고 CI 가 없다. `__init__.py` 의 `__version__` 이 `0.2.4` 인데 `pyproject.toml` 은 `0.3.3` 이어서 버전 표기도 어긋난다.
4. 판정: 성과를 주장하지 않는 데이터 도구이므로 앵커 5.

심층 T 5 (판정 T 5) — 투자 성과 주장이 없는 DART API 래퍼.

## 수요 신호

이슈 53개(PR 제외)를 전부 봤다. 반응은 최대 1, 댓글은 최대 3 으로 참여가 작다. Discussions 는 꺼져 있다. 이슈의 절반 이상이 DART 쪽 변경·누락으로 생긴 오류나 초보 사용법 질문이라 버그는 넣지 않았고, 데이터 수요·운영 불만만 16건 뽑았다(demand 7, pain 6, gap 3).

- 재무제표 표준화·가공: 회사마다 매출액·판관비 항목이 빠지거나 `account_id` 가 없다(#23). 지배기업 귀속 순이익 계정을 식별하기 어렵다(#31). 메인테이너는 두 번 모두 "API 데이터를 그대로 가져온다", "임의로 가공하기 어렵다"며 라이브러리 밖의 일로 선을 그었다. 표준화된 한국 재무 데이터는 사용자가 원하는데 이 라이브러리는 하지 않는 영역이다(gap).
- 데이터 범위: 2015년 이전 재무제표(#21, Open DART 가 2015년 이후만 제공), 금융업 재무제표(#30, 단일회사 API 에서 제외), 2017년 이전 정기보고서 목록 누락(#54). 원천 API 의 한계라 라이브러리로는 못 메운다.
- 속보성: 2Q·3Q 재무 데이터가 언제 올라오는지 묻는 이슈가 두 번(#48·#49) 나왔다. 회사별 실적 공시 시점을 모르는 사용자가 있다는 뜻이고, "재무 데이터가 올라오면 알려 주는" 알림 수요로 읽을 수 있다.
- 본문 검색: 사업보고서·주석에서 '주요 제품', '사업분야', '시장전망' 같은 키워드로 문단을 찾고 싶다(#19). 메인테이너는 기능으로 넣을 계획이 없다고 답했다(gap). LLM 요약·RAG 가 들어갈 자리다.
- 정정공시 추적(#7): `final` 옵션으로 해결됐지만 정정 전후 차이를 보고 싶다는 수요의 출발점이다.
- 운영 불만: 객체를 만들 때마다 `corpCode.xml` 을 받아 API 호출 수가 늘어난다(#16, 이후 하루 캐시로 해결). 이름이 같은 회사가 있으면 다른 회사 공시가 나온다(#52). 스크래핑 기능은 DART 홈페이지가 바뀌면 못 쓰게 된다는 불안(#39). #51 의 traceback 에는 사용자가 `api_keys[api_key_idx]` 로 여러 키를 돌려 쓰는 대량 수집 코드가 보인다(일일 호출 한도 회피로 추정, 인용은 넣지 않음).
- 설치 어려움: 비개발자 투자자가 pip·cmd·주피터부터 막힌다(#34·#35·#39 "#초보"). 파이썬 없이 쓰는 서비스 수요로 읽는다. #34 본문에는 실제 API 키로 보이는 문자열이 붙어 있어 그 구절은 인용하지 않았다.
- 호스팅 버전·MCP·API 비용 불만 요청: 없음. 이슈 활동이 2024-11 이후 거의 멈췄고, API 가 무료라 비용 불만이 생길 여지가 없다.

## 내 투자에 쓰려면

- 실행: Open DART 에서 키를 받아 `.env` 에 `DART_API_KEY` 를 두고 `uv tool install opendartreader` → `dart list "삼성전자" --start 2026-01-01 --pretty`, `dart finstate "005930, 000660" 2025`, `dart event 005930 자기주식취득` 식으로 쓴다(Python 3.13 이상 필요). 라이브러리로는 `OpenDartReader().list(start=오늘, end=오늘)` 로 전 종목 당일 공시, `list_date_ex()` 로 접수 시각까지 받는다.
- 주의점:
  - `list_date_ex()` 는 기본 `cache=True` 라 같은 날짜 URL 을 한 번 받으면 파일 캐시를 계속 돌려준다. 당일 공시를 주기적으로 긁는 알림 용도라면 반드시 `cache=False` 를 써야 한다. 그런데 `cache=False` 경로는 `requests.get(url, headers)` 로 headers 를 query 파라미터 자리에 넘겨 User-Agent 가 빠진다(코드 읽기로 확인, 실행은 안 함).
  - 모든 요청에 timeout·재시도가 없다. 워커에 넣으면 걸린 요청이 프로세스를 멈출 수 있으니 바깥에서 타임아웃을 건다.
  - `list_presenter` 는 `verify=False` 로 TLS 검증을 끈 채 `dart.fss.or.kr` 에 POST 한다(`urllib3` 경고도 전역으로 끈다).
  - 실행한 디렉터리에 `docs_cache/` 를 만들고 원문·목록 캐시를 무기한 쌓는다. 작업 디렉터리를 정해 두고 주기적으로 지운다.
  - 이름 조회는 첫 일치 회사를 고른다(#52). 종목코드 6자리나 고유번호 8자리로 부른다.
  - 재무 숫자는 공시 원본 그대로라 회사 간 비교 전에 계정 매핑을 직접 해야 한다(#23·#31). 금융업·2015년 이전은 없다.
  - 스크래핑 함수(`sub_docs`·`attach_files`·`list_date_ex`)는 DART 개편 때 깨지고 수정이 늦다(#55·#57 이 2024 부터 열려 있음).

## 인디 관점 메모

- 차용: GuruNote 에 한국 공시를 붙인다면 이 라이브러리는 고유번호 변환·주요사항보고 36종·지분공시·재무제표 호출을 바로 가져다 쓸 수 있는 얇은 계층이다(MIT). 다만 알림 워커의 핵심인 "당일 신규 공시 폴링"은 캐시·timeout 문제 때문에 `list.json` 을 직접 부르거나 해당 함수를 옮겨 고쳐 쓰는 편이 낫다. `list_date_ex` 의 접수 시각 스크래핑 방법(Open DART 목록에는 시각이 없다)은 속보성 알림에 쓸 만한 요령이다.
- 경쟁: 라이브러리 자체는 경쟁자가 아니다. 경쟁은 DART MCP 서버들(korean-dart-mcp 등)과 DartPoint AI 같은 무료 AI 공시 서비스, 증권사 앱의 무료 공시 알림이다. "DART 공시 알림" 자체로는 무료 대체재가 많아 돈을 받기 어렵다.
- 공백: 이슈에서 반복되는 표준화 재무 데이터(#23·#31), 본문 키워드·문단 검색(#19), 실적 공시가 올라오는 순간의 알림(#48·#49), 비개발자용 무설치 사용(#34·#35)은 라이브러리가 명시적으로 안 하는 일이다. GuruNote 의 차별점은 "SEC 13F·Form 4 와 DART 지분공시·주요사항을 같은 관심 종목·같은 텔레그램 채널에서 한국어 요약으로" 묶는 교차 시장 구성에 있다. 한국 투자자는 미국·한국 종목을 함께 들고 있는데, 두 시장 공시를 한 곳에서 알려 주는 서비스는 이번 조사 범위에서 보이지 않았다(`dartlab` 이 DART+SEC 를 함께 다루지만 분석용 라이브러리다).
