## 무엇·어떻게

- 구성(`src/FinanceDataReader/`, 약 3.3천 줄): 소스별 모듈 `krx/`·`naver/`·`yahoo/`·`fred/`·`ecos/`·`investing/`·`wikipedia/`·`nasdaq/`, 차트 `chart/`(plotly). `data.py` 가 심볼 접두어(`KRX:`·`NAVER:`·`YAHOO:`·`FRED:`·`ECOS:`·`TSE:` 등)로 소스를 고른다. 접두어가 없으면 한국 종목코드는 네이버 차트 API(`fchart.stock.naver.com`), 그 밖은 Yahoo `query2 v8/chart` 로 간다.
- **KRX 로그인 필수화 이후 구조가 바뀌었다.** KRX 정보데이터시스템이 2026-02-27 무렵 로그인한 세션만 받도록 바뀌었다(#266·#267). 메인테이너는 사용자에게 ID/PW 를 받지 않는 쪽을 골랐다. 별도 레포 `FinanceData/fdr_krx_data_cache`(2026-03-09 생성)의 GitHub Actions 가 메인테이너의 KRX 계정(Secrets `KRX_ID`/`KRX_PW`)으로 평일 10분마다 수집해 CSV 로 커밋한다. 라이브러리는 이 CSV 를 `raw.githubusercontent.com` 에서 읽는다(`KrxMarcapListingCache`, `KrxStockListingCache`, `KrxDelistingCache`, `KrxIndexReaderCache`, `KrxSnapReaderCache`). KS11·KQ11·KS200 지수, `StockListing('KRX'|'KOSPI'|…)`, 상장폐지 목록이 여기에 걸려 있다. 캐시 파일 날짜는 KRX 의 `max_work_dt` 를 비로그인 호출로 받아 정한다.
- 이 구조의 약점은 이슈로 드러났다. KRX 는 90일마다 비밀번호 변경을 요구한다. 변경을 놓치면 수집 로그인이 실패하고 당일 CSV 가 없어 전 사용자에게 `HTTP Error 404` 가 난다(2026-06-08·09-08, #276·#277·#284·#286, 캐시 레포 #1). 이때도 워크플로는 `success` 로 끝나 실패가 바로 알려지지 않는다(캐시 레포 #1 댓글).
- Release Note 0.9.110(wiki) 기준으로 **KRX 개별 종목 가격(`KRX:005930`)과 개별 지수 구성종목은 지원하지 않는다**. 그런데 README 는 아직 `fdr.DataReader('KRX:000100') # 1995-05-02 ~ 현재` 를 예시로 든다. 코드상 `KrxDailyReader` 는 로그인 없이 `data.krx.co.kr` 를 직접 호출한다.
- 네이버 의존이 크다. 한국 종목 기본 시세, 재무제표(`navercomp.wisereport.co.kr` 의 `encparam` 을 긁어 JSON 호출), ETF 목록(KR·US), 해외 종목 목록이 모두 네이버다. 네이버 증권이 2026-09-10 개편을 예고했고(#285), 메인테이너는 "확인해보도 업데이트 혹은 대응 계획을 따로 말씀 드리겠습니다" 라고만 답했다. 대응은 아직 확인되지 않는다.
- LLM 없음. 실행 비용 0원이다. 대신 소스 사이트가 바뀔 때마다 깨지고, 고치는 사람은 메인테이너 한 명이다(이력: 2024-07 KRX Referer 필수화, 2024-07 KRX 2년 조회 제한, 2024-09 Yahoo v7 인증, 2025-07 영문 포함 종목코드, 2026-01 KRX 사이트 변경, 2026-02 로그인 필수화).
- 참고: `krx/listing.py` 의 `KrxStockListing.read()` 는 `ssl._create_default_https_context = ssl._create_unverified_context` 로 프로세스 전체의 SSL 검증을 끈다. 현재 `data.py` 는 이 클래스를 쓰지 않고 캐시 버전을 쓴다. 레포 안 `docs/_build/` 는 Sphinx 빌드 산출물(jquery 등)이고 실행 코드가 아니다. 수상한 스크립트나 지시문은 없었다.

## 성과 주장의 신뢰도

1. 주장 목록 — README·wiki Release Note·docs 에 수익률·적중률·샤프 같은 성과 주장이 없다. README 첫 설명은 "The FinanceDataReader is financial data reader(crawler) for finance." 로 기능만 말한다. 링크된 노트북("S&P500 가격 데이터 수집과 수익률 분석")은 데이터 사용 예제이고 전략 성과 주장이 아니다.

3. 검증 수단 — 해당 없음(전략·백테스트가 없는 데이터 도구). 데이터 품질 쪽 한계로 다음이 이슈에 드러나 있다. 네이버 시세는 수정주가지만 거래량은 수정하지 않는다(#85). 상장폐지 종목은 수정주가가 없다(#73). KOSDAQ GLOBAL 이 `Market` 컬럼에서 따로 잡혀 필터 시 누락된다(#281). 장 전후 최근일 시가가 0 으로 나온다(#274). `^KS200`(Yahoo)과 `KS200`(KRX)의 값이 다르다(#280). `tests/` 에 pytest 53개가 있지만 CI 설정은 없다.
4. 판정 — 성과를 주장하지 않는 데이터 인프라이므로 앵커 5.

심층 T 5 (판정 T 5) — 성과 주장이 없는 한국 시장 데이터 크롤러.

## 파생·상용화

- 포크: 상위 10개 중 최고가 `xiaolai/FinanceDataReader` ★21(2020년 정지)이고, 나머지는 ★2 이하의 개인 수정본이다. 파생 포크는 없다. 파생은 의존 형태다.
- 자매 레포: 같은 메인테이너의 `FinanceData/marcap`(1995년~ 전종목 일별 시가총액 데이터셋)과 `fdr_krx_data_cache` 도 같은 KRX 로그인·비밀번호 주기 문제를 겪는다(marcap #35).
- MCP 서버: `Mrbaeksang/korea-stock-analyzer-mcp` 는 FinanceDataReader·pykrx 로 시세·상장 정보를 받아 "투자대가 6인 전략" 분석을 MCP 로 낸다. `jjlabsio/korea-stock-mcp` 는 DART·KRX 공식 API 를 쓴다. 한국투자증권 `open-trading-api` 도 MCP 를 내놓았다.
- 경쟁·대체: `sharebook-kr/pykrx`(★약 1.1k)가 같은 KRX 스크래핑 계열로 같은 날 다운됐다(pykrx #276, 댓글 24). `beaten-by-the-market/krx-data-api` 는 `KRX_ID`/`KRX_PW` 로그인 세션을 감싼 클라이언트다. DART OpenAPI 기반 `kofinance` 는 이슈 댓글에서 대안으로 홍보됐다(#266·#267, "무료 (일 1,000건)"). 공식 쪽에는 KRX Data Marketplace OPEN API, 공공데이터포털 `금융위원회_주식시세정보`(무료, 일 단위), 증권사 Open API(한국투자증권은 이용료 없이 계좌만 요구)가 있다.
- 이 레포를 감싼 유료 서비스는 찾지 못했다(웹 검색 3회).

## 내 투자에 쓰려면

- `pip install finance-datareader`(또는 `uvx --from finance-datareader fdr price 005930 --start 2024`)로 설치한다. `fdr.DataReader('005930', '2020')`(네이버), `fdr.StockListing('KRX')`(GitHub 캐시), `fdr.SnapDataReader('NAVER/FINSTATE-2Q/005930')`(분기 연결 재무), `fdr.DataReader('FRED:T10Y2Y')`·`fdr.DataReader('USD/KRW')` 식으로 쓴다.
- 주의 ① `StockListing('KRX')`·KS11 지수는 메인테이너 계정으로 모은 GitHub CSV 다. 90일마다 1~2일 끊기므로 전일 목록을 로컬에 두고 404 면 그걸 쓰는 폴백을 짠다. ② `KRX:005930`(KRX 직접 가격)은 로그인화 이후 지원 목록에서 빠졌다. README 예시를 믿지 않는다. ③ 네이버 개편(2026-09-10) 뒤 기본 시세·재무제표 경로가 깨질 수 있으니 버전을 자주 올리고 결과를 검증한다. ④ 거래량은 수정 전 값이고 상장폐지 종목은 수정주가가 없으니, 백테스트에 쓰면 직접 보정한다(#73·#85). ⑤ `StockListing` 의 `Market` 필터는 KOSDAQ GLOBAL 을 빠뜨린다. 시장별 목록은 `StockListing('KOSDAQ')` 로 받는다(#281).
- 개인 리서치·스크리닝·장기 백테스트의 입력으로는 가장 간편하다. 자동매매 실시간 신호의 소스로는 증권사 API 를 쓴다.

## 인디 관점 메모

- 공백: 한국 개인 퀀트의 사실상 표준 무료 데이터 경로(FDR·pykrx)가 모두 **KRX 로그인·네이버 개편 같은 소스 정책 하나에 같이 깨지는** 구조다. FDR 은 1인 메인테이너 계정과 GitHub Actions 에 기대는 임시 캐시로 버틴다. 수요는 "무료로 안 깨지는 한국 시세·목록·재무"인데, 지불 의사를 말한 사람은 이 레포에 없다(yfinance 의 "월 $10" 같은 발언이 없음). 사용자 대부분은 무료를 기대하는 파이썬 사용자다.
- 기회 방향: KRX 데이터 재배포는 약관상 막혀 있다. 그러니 GitHub 캐시안을 따라 "KRX 캐시 재판매"로 가지 않는다. 라이선스가 명확한 소스(공공데이터포털 금융위 시세, DART OpenAPI, 사용자 본인의 증권사 API 키, KRX OPEN API)를 **FDR 과 같은 함수 모양(`DataReader`/`StockListing`/`SnapDataReader`)으로 감싼 호환 레이어**가 낫다. 여기에 사용자 로컬 증분 캐시와 소스 장애 시 자동 폴백을 붙인다. FDR 코드를 쓰는 기존 노트북·MCP 서버를 그대로 옮겨 올 수 있다. 무료 오픈소스 + 장애 감시·대체 소스 알림 같은 얇은 유료층 정도가 현실적이다.
- 데이터 공백(퀀트 수요, 이 레포가 못 채움): 시점 기준(point-in-time) 지수 구성종목·편출입 이력, 상장폐지 포함 수정주가(생존 편향 없는 백테스트), 한국 국고채 수익률, 1996년 이전 시세. 특히 앞의 두 개는 한국 백테스트 신뢰도에 직결되는데 무료로 정리된 곳이 드물다.
- 차용할 부분: ① 접두어로 소스를 고르는 단일 진입점(`NAVER:`·`KRX:`·`FRED:`) — 소스 교체를 사용자 코드 변경 없이 할 수 있다. ② `fdr` CLI 의 `-f json|markdown` 출력 — LLM 에이전트 도구로 바로 쓸 수 있는 모양이다. ③ 반면교사로, 캐시 수집 실패가 워크플로 `success` 로 가려지지 않게 하는 장애 감시.
