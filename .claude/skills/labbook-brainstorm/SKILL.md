# 브레인스토밍

설계 근거: `docs/ai-discussions/20260926-주식-오픈소스-전수조사.md` §3.1-E (문헌 근거 포함), §1.2 문제 3·4.

LLM 아이디어는 흔한 쪽으로 쏠리고, 실행해 보면 평가가 크게 떨어진다. 그래서 입력과 발산 방식을 고정한다.

## 입력

- `signal` 행 (`labbook-query` 스킬의 스키마 참고)
- 심층분석 노트 `topics/<주제>/notes/*.md`
- GuruNote 경쟁·규제 조사 (읽기만 한다): `~/Workspace/Indy/GuruNote/docs/ai-discussions/20260923-사전조사-경쟁-시장.md`, `20260926-아이디어-관심기업-공시-알림.md`
- 사용자 자산·제약: 1인 개발, 한국 투자자 대상, GuruNote 워커(SEC 수집)·텔레그램 봇·`claude -p` 가공, 월정액 LLM
- 사용자가 낸 아이디어 (같은 풀에 넣는다)

레포 목록만 보고 발산하지 않는다.

## 흐름

1. **JTBD**: 신호를 군집해 "<상황>에서 <동기>하려는 <누구>가 <결과>를 원한다" 문장으로 만든다. 문장마다 근거 signal id 와 개수를 붙인다.
2. **렌즈별 발산**: JTBD × 렌즈마다 아이디어를 낸다. 렌즈는 아래 7개다.
   - 호스팅·관리형
   - 한국화(KRX·DART·KIS, 한국어)
   - 언번들(한 기능만 떼기)
   - 곡괭이(데이터·MCP·에이전트 스킬 공급)
   - 신뢰·검증(AI 신호의 포워드 성적표)
   - 콘텐츠·교육
   - GuruNote 자산 결합
3. **군집·중복제거**: 비슷한 아이디어를 묶고 군집마다 대표 하나를 남긴다.
4. **수렴**: 여섯 기준에 1~5 절대점수를 매긴다.
   - 기준: 수요 근거, 기존 대안 대비 차별성(증권사 무료 기능 포함), 1인 실현성, 규제 위치, 수익화, 자산 재사용
   - 둘씩 붙여 비교하는 방식은 쓰지 않는다.
   - 상위권에는 사전부검("6개월 뒤 실패했다면 그 이유 3가지")을 붙인다.
5. **사용자 선택**: 상위 후보를 점수·사전부검과 함께 보여 주고 멈춘다. 원페이저로 만들 3개는 사용자가 고른다. LLM 점수는 순서를 정하는 보조일 뿐이다.

## 규제 위치 라벨 (모든 아이디어에 필수)

| 라벨 | 조건 |
|---|---|
| 무료 정보·도구 | 대가 없이 정보·도구 제공 |
| 유사투자자문 신고 필요 | 유료로 불특정 다수에게 비개인화 추천 (자본시장법 101조) |
| 등록업(인디 불가) | 개인 맞춤 추천, 양방향 유료 회원제, 자동매매·카피트레이딩 연동 |

## 출력

1. 원페이저 `topics/<주제>/ideas/<slug>.md`

```markdown
# <아이템명>
- JTBD:
- 수요 근거: signal #id… (레포 N곳, 반응 합계) · 참고 문서 절
- 기존 대안·경쟁:
- 규제 위치: <라벨>
- 1인 실현성·재사용 자산:
- 사전부검: 1. 2. 3.
- 검증 가설: 누가 무엇을 할 것 / 성공 기준 / 접을 기준 / 판정일
```

2. 개인 툴킷 `topics/<주제>/toolkit.md`: 레포마다 용도, 실행법, 신뢰 주의점을 적는다. AI 신호는 리서치 초안으로만 쓰고, 백테스트 수익은 믿지 않는다. 컷오프 이후 구간·페이퍼 트레이딩으로만 본다.
3. `idea` 행 — 발산한 아이디어 전부를 `draft` 로, 사용자가 고른 것은 `shortlist` 로 넣는다. 사용자가 뺀 것은 `dropped` 와 사유를 넣는다.

```sh
sqlite3 labbook.db "INSERT INTO idea (topic, title, jtbd, lens, signal_ids, scores, status, reason, doc_path, created_at)
VALUES ('<주제>', '<제목>', '<JTBD>', '<렌즈>', '[12,31]', '{\"수요\":4,…}', 'draft', NULL, NULL, datetime('now'));"
```

4. `topics/<주제>/index.md` 에 원페이저 한 줄 카탈로그를, `log.md` 에 `## [YYYY-MM-DD] brainstorm | 요약` 을 추가한다.

검증은 LabBook 이 아니라 해당 제품 레포(GuruNote 또는 신규)의 아이디어 문서·`/forge:plan-gen` 으로 넘긴다.
