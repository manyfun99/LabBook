# 브레인스토밍

설계 근거: `docs/ai-discussions/20260926-주식-오픈소스-전수조사.md` §3.1-E (문헌 근거 포함), §1.2 문제 3·4.
절차 확정: `docs/ai-discussions/20260928-주식-오픈소스-조사-실행-4차.md` §3.1~§3.6.

LLM 아이디어는 흔한 쪽으로 쏠리고, 실행해 보면 평가가 크게 떨어진다. 그래서 입력과 발산 방식을 고정한다.

## 입력

- `signal` 행 (`labbook-query` 스킬의 스키마 참고)
- 심층분석 노트 `topics/<주제>/notes/*.md`, 카탈로그 `topics/<주제>/index.md`
- GuruNote 경쟁·규제 조사: `~/Workspace/Indy/GuruNote/docs/ai-discussions/20260923-사전조사-경쟁-시장.md`, `20260926-아이디어-관심기업-공시-알림.md`
  — 주 작업 디렉터리 밖이므로 **메인 세션이 필요한 절만 `.cache/brainstorm/gurunote-brief.md` 로 추린다.** 서브에이전트가 직접 열지 않는다.
- 사용자 자산·제약: 1인 개발, 한국 투자자 대상, GuruNote 워커(SEC 수집)·텔레그램 봇·`claude -p` 가공, 월정액 LLM
- 사용자가 낸 아이디어 (같은 풀에 넣는다)

레포 목록만 보고 발산하지 않는다.

## 흐름

### 1. JTBD — 레포가 아니라 인용 내용으로 묶는다

신호 전량을 작업 파일로 내린다(`id · kind · weight · repo · quote` 탭 구분). 레포 이름은 **근거 계산용**으로만 쓰고 군집 키로 쓰지 않는다.

1. 인용이 말하는 **요구·불편의 내용**으로 묶는다. 같은 레포의 신호가 여러 군집에 흩어져도 된다.
2. 군집마다 "\<상황\>에서 \<동기\>하려는 \<누구\>가 \<결과\>를 원한다" 문장을 쓴다. 8~12개를 목표로 한다.
3. 문장마다 `signal_ids` · **근거 레포 수** · weight 합을 붙인다.
4. **근거 레포가 1곳뿐이면 `단일`**, **한 레포가 근거의 50% 를 넘으면 `⚠`** 를 표시한다. 둘 다 6기준의 "수요 근거" **점수 상한이 3** 이다. 신호가 많은 레포가 군집을 끌고 가는 것을 막는 장치다.
5. 확인: 근거 레포 2곳 이상인 문장이 **70% 이상**이어야 한다. 미달이면 군집을 다시 나눈다.

JTBD 로 승격하지 않은 맥락(예: 상용화 갈등, 사용자끼리 모이려는 움직임)은 "부가 관찰"로 따로 적어 발산 재료로만 쓴다.

### 2. 렌즈별 발산 — 렌즈당 서브에이전트 1개, 배치로 나눈다

JTBD × 렌즈마다 아이디어를 낸다. 렌즈는 7개다.

- 호스팅·관리형 / 한국화 / 언번들 / 곡괭이 / 신뢰·검증 / 콘텐츠·교육 / GuruNote 자산 결합

**분할**: 렌즈 1개당 서브에이전트 1개, 배치 4 + 3 으로 돌린다. 서로의 출력을 보지 못하게 해서 앵커링을 막는다. **서브에이전트는 파일만 쓰고, DB·문서는 메인이 쓴다.**

공통 입력 4개를 경로로 준다 — `.cache/brainstorm/brief.md`(배경·자산·제약·규제 라벨), `jtbd.md`, `gurunote-brief.md`, `signals.tsv`.

규칙:
- 렌즈당 **5~8개**. 규제 라벨 필수(아래 3분류만).
- `signal_ids` 는 실재하는 id 여야 한다. 신호 근거 없이 사용자 자산·제약에서만 나온 아이디어는 **빈 배열 `[]`** 로 두고, 수렴에서 "수요 근거" **1점 고정**이다.
- **서브에이전트는 웹을 쓰지 않는다.** 기존 대안은 조사 기록 범위에서 "추정"으로 적고 모르면 "확인 못 함"이라고 쓴다. 실제 경쟁 확인은 메인이 상위 후보에만 한다.
- 출력은 `.cache/brainstorm/ideas-<렌즈>.jsonl` 한 줄 한 아이디어:
  `{"title","lens","jtbd_ids","signal_ids","pitch","alt","regulation","feasibility","reuse"}`
- 예산: 렌즈당 3~6분, 배치당 6~10분. 한 배치가 15분을 넘으면 남은 렌즈를 다음 배치로 미룬다.

### 3. 군집·중복제거

비슷한 아이디어를 묶고 군집마다 대표 하나를 남긴다(목표 12~18). 묶인 아이디어의 `signal_ids`·`lens` 는 대표에 합친다.
**합쳐진 쪽도 버리지 않는다** — `dropped` + `중복: <대표 제목>` 으로 함께 적재해 발산 이력을 남긴다. `.cache/` 는 gitignore 라 적재하지 않으면 사라진다.
대표 제목이 소속 원본 제목과 같으면 그 원본은 **승격된 것이므로 dropped 행을 만들지 않는다**(같은 파일에 title 이 두 번 나오면 `idea-load` 가 거부한다).

### 4. 수렴 — 6기준 절대점수

대표마다 1~5 절대점수를 매긴다. 둘씩 붙여 비교하지 않는다. 앵커는 고정한다.

| 기준 | 1 | 3 | 5 |
|---|---|---|---|
| 수요 근거 | 단일 레포 신호 1~2건, 또는 신호 근거 없음(빈 `signal_ids` — **1 고정**) | 레포 2곳 이상·신호 5건 이상 | 레포 4곳 이상·신호 12건 이상·weight 합 50 이상 |
| 차별성 | 증권사 앱·네이버 금융이 이미 무료로 준다 | 대안은 있으나 한국어·한국 데이터·자동화에서 빈다 | 조사 기록·경쟁 문서에서 같은 것을 하는 곳을 찾지 못했다 |
| 1인 실현성 | 상시 운영 인프라나 데이터 계약이 필요하다 | 4주 안 MVP, 주 1회 운영 | 기존 자산에 얹어 2주 안 |
| 규제 위치 | 등록업(인디 불가) | 유사투자자문 신고 필요 | 무료 정보·도구 |
| 수익화 | 과금 경로가 없다 | 유료 전환 경로는 보이나 근거는 유추다 | 같은 영역의 실제 과금 사례를 조사에서 확인했다 |
| 자산 재사용 | 새로 다 만든다 | 패턴만 재사용한다 | 기존 워커·봇·`claude -p` 파이프라인을 그대로 쓴다 |

- **차별성 5는 "찾아봤는데 없다"일 때만 준다.** 검색이 실패했거나 확인하지 못했으면 **4 를 상한**으로 두고 그 사실을 적는다 — "안 찾아봤다"와 "없다"를 구분한다.
- **규제 1점(등록업)은 후보표에서 뺀다.** 뺀 것도 `dropped` + 사유로 남긴다.
- 상위 6개에만 ① **실제 경쟁 확인**(웹 검색·경쟁 문서) ② **사전부검** 3줄("6개월 뒤 실패했다면 그 이유")을 붙인다. 경쟁 확인 결과로 차별성·수익화 점수가 바뀌면 표에 그 사실을 적는다.
- 합산 순위는 순서를 정하는 보조다. 최종 결정으로 쓰지 않는다.

### 5. 사용자 선택

후보표(상위 8개: 제목·JTBD·근거·6점수·라벨)를 한 장으로 보여 주고 **버튼 2문항**으로 묻는다 — ① "상위 4개 중 원페이저로 만들 것"(다중 선택) ② "차순위 4개 중 추가할 것(없으면 없음)"(다중 선택). 후보가 8개보다 적으면 문항 수를 줄인다.
계획의 원페이저 수와 선택 수가 다르면 **범위가 달라지므로 다시 확인**한다.
**0개면 멈춘다.** 억지로 쓰지 않고 입력(신호·렌즈)부터 재검토한다.

## 규제 위치 라벨 (모든 아이디어에 필수)

| 라벨 | 조건 |
|---|---|
| 무료 정보·도구 | 대가 없이 정보·도구 제공 (자본시장법 §7③ 개별성 없는 조언) |
| 유사투자자문 신고 필요 | 유료로 불특정 다수에게 단방향·비개별 추천 (§101) |
| 등록업(인디 불가) | 개인 맞춤 추천, **온라인에서 대가를 낸 고객과 의견을 주고받는 형태**(2024-08 개정 단서), 자동매매·카피트레이딩 연동 |

개별성은 받는 사람 수가 아니라 투자목적·재산상황·투자경험을 반영하는지로 본다(대법원 2018도4413). 애매하면 **더 무거운 라벨**을 고른다.

## 출력

### 1. 원페이저 `topics/<주제>/ideas/<slug>.md`

파일명은 영문 kebab-case 2~4단어다. `idea.doc_path` 는 **레포 루트 기준** `topics/<주제>/ideas/<slug>.md`, `index.md` 링크는 주제 디렉터리 기준 `ideas/<slug>.md` 로 적는다.

```markdown
# <아이템명>
- **JTBD**:
- **수요 근거**: signal #id… (N건, 레포 N곳, 반응 합계 N) · 대표 인용 · 참고 문서 절
- **기존 대안·경쟁**:
- **규제 위치**: <라벨>
- **1인 실현성·재사용 자산**:
- **사전부검 — 6개월 뒤 실패했다면**: 1. 2. 3.
- **검증 가설**: 누가 무엇을 할 것 / 성공 기준 / 접을 기준 / 판정일
- **범위 밖**:
```

### 2. 개인 툴킷 `topics/<주제>/toolkit.md`

대상은 **개인 활용도 P≥4 인 레포 전부 + 정밀 판정이 없는 심층분석 대상**이다. 레포마다 용도·실행법·신뢰 주의점을 적는다. 실행법은 노트의 설치·의존성 기록에서 가져오고, 실제 구동은 하지 않는다(사용자가 필요할 때 한다).

끝에 두 절을 더 둔다.
- **AI 신호를 다루는 규칙** — 백테스트 수익은 믿지 않는다. 컷오프 이후 구간·페이퍼 트레이딩으로만 본다. 조사에서 확인된 반례를 사례로 든다.
- **쓰지 않기로 한 것** — P≤3 인 레포를 한 줄 사유로 남긴다.

사용 기록은 사용자가 `log.md` 에 `## [YYYY-MM-DD] use | owner/repo` 로 남긴다(UTC).

### 3. `idea` 행 — `labbook idea-load` 로 적재한다

발산 raw 전량을 넣는다. 대표는 `draft` + 6점수, 합쳐진 것은 `dropped` + `중복: <대표 제목>`, 사용자가 고른 것은 `shortlist` + `doc_path`, 규제·미선택으로 뺀 것은 `dropped` + 사유다.

```sh
python3 -m labbook idea-load <주제> .cache/brainstorm/idea-draft.jsonl
```

한 줄 형식 (`{"title","jtbd","lens","signal_ids","scores","status","reason","doc_path"}`):

```json
{"title":"…","jtbd":"J2+J9","lens":"한국화","signal_ids":[274,285],"scores":{"수요":4,"차별성":4,"실현성":3,"규제":5,"수익화":3,"재사용":2},"status":"draft","reason":null,"doc_path":null}
```

- 파일 전체를 검증한 뒤 한 트랜잭션으로 쓴다. 한 줄이라도 틀리면 아무것도 쓰지 않고 `<경로>:<줄>` 로 알려 준다.
- `(topic, title)` 기준 upsert 이고 **파일에 담긴 키만 갱신한다** — 상태만 바꾸는 줄이 `jtbd`·`lens`·`scores` 를 지우지 않는다. 값을 비우려면 `null` 을 명시한다.
- 새 행에는 `signal_ids`·`status` 가 필수다. `dropped`·`shortlist` 로 바꾸는 줄은 `reason`·`doc_path` 를 **같은 줄에 담는다**(검증은 DB 가 아니라 파일만 본다).
- **적재 후에는 제목을 바꾸지 않는다.** 제목이 갱신 키라서, 바꾸면 옛 행이 그대로 남는다.

### 4. 카탈로그·로그

`topics/<주제>/index.md` 에 원페이저·툴킷 한 줄 카탈로그를, `log.md` 에 `## [YYYY-MM-DD] brainstorm | 요약` 을 추가한다. **손으로 쓰는 날짜도 UTC 로 맞춘다**(`labbook` 이 자동으로 남기는 줄과 같은 기준).

마지막에 `python3 -m labbook export` 하고 `data/*.jsonl` 을 커밋한다.

## 재개

중간 산출물은 `.cache/brainstorm/`(gitignore)에 있다. 끊기면 아래로 판단한다.

| 단계 | 완료 표시 | 재개 |
|---|---|---|
| 브리프 | `signals.tsv`·`gurunote-brief.md`·`brief.md` | 없는 파일만 |
| JTBD | `jtbd.md` 에 8~12행 + 70% 확인 줄 | 다시 만든다(입력이 결정론적이라 싸다) |
| 발산 | `ideas-<렌즈>.jsonl` 7개, 각 5줄 이상 | **렌즈 단위** — 없거나 모자란 렌즈만. 다시 돌리기 전에 그 jsonl 을 지운다 |
| 수렴 | `candidates.md` 에 대표와 6점수 | 7개 jsonl 부터 다시 합친다 |
| 적재 | `idea` 행 수 = raw 건수 | 같은 파일로 다시 돌린다(upsert 라 안전) |
| 원페이저 | `topics/<주제>/ideas/*.md` | 없는 slug 만 |

검증은 LabBook 이 아니라 해당 제품 레포(GuruNote 또는 신규)의 아이디어 문서·`/forge:plan-gen` 으로 넘긴다.
